# 研发流程编排

定位本轮任务与动作，选定阶段 Skill，按其指令完成当前获准的工作。业务进度以目标项目的任务记录和人工决定为准。

## 接收输入

1. 优先定位用户点名的项目与任务，其次采用当前工作区。核对目标项目实际存在且适用的约定，按项目路径保存业务代码与任务产物。
2. 接续任务时定位已有任务 README。新任务先核对是否已有相同目标的记录；默认任务目录为 `docs/ai-development/<实际任务名>/`。有多个候选且会影响本轮操作时，先只读定位，再请用户选择。
3. 实际读取用户提供的附件、链接、原型及代码线索。记录影响判断的来源和读取状态（已读／部分可读／无法读取）。区分用户要求、可核实现状、AI 建议与待决问题。材料不足时继续处理已有依据支持的部分，列明具体缺口。
4. 根据本轮动词选择动作。只有入口名称且没有可定位的任务时，询问本次目标或要接续的任务。用户提供了足够信息时，直接进入对应的实际工作。

## 阶段路由

下表给出本发行包中各 Skill 的相对入口。用户沿用 R01 至 R09 的阶段简称时，按下表顺序定位。每个阶段从自身目录读取执行指南和模板。

| 阶段与常见请求 | 调度目标 |
| --- | --- |
| 熟悉项目、定位旧实现和复用依据 | [项目现状评估](../sdlc-project-assessment/SKILL.md) |
| 整理需求、复述业务过程、核对边界案例 | [需求分析与确认](../sdlc-requirements-analysis/SKILL.md) |
| 判断改动影响、比较实现路径与兼容代价 | [变更影响分析](../sdlc-impact-analysis/SKILL.md) |
| 明确负责功能、排除项、依赖及对接责任 | [交付范围界定](../sdlc-scope-definition/SKILL.md) |
| 定义接口契约、依赖关系与排序 | [接口契约设计](../sdlc-interface-design/SKILL.md) |
| 拆分批次、确定测试范围与验收计划 | [分批交付规划](../sdlc-delivery-planning/SKILL.md) |
| 实现、调试、验证、验收当前获准的批次 | [批次实施与验收](../sdlc-batch-execution/SKILL.md) |
| 按实际实现编写对接文档、联调与交付 | [集成对接与交付](../sdlc-integration-handoff/SKILL.md) |

**执行路由。** 优先使用目标项目当前实际可用的同名阶段 Skill。宿主支持显式选择时选用该 Skill；采用文件指令的项目则打开对应链接。读取其 `SKILL.md`，再按该文件的相对引用读取其 `references/` 中的阶段规范。把本轮意图、材料位置和读取限制、任务入口、正式阶段、当前授权及待决问题带入同一个任务。依照阶段规范完成交付，沿用已核实材料。

仅在与任务相关时加载阶段。项目或宿主明确停用、缺少目标 Skill 或无法读取其规范时，说明受影响的操作和路径；仅继续已有约定支持的独立工作。阶段间的资料引用仅用于核对依据，避免递归调度入口。必须据实报告使用的是已选择的 Skill 还是已读取的文件。

## 路由与实际进度

- **讲解现有功能或改动。** 用户想了解功能或技术点怎么实现、当初为什么这样设计，或回顾某次已经发生的改动时，使用[项目实现讲解](../sdlc-project-explainer/SKILL.md)。如有影响讲解的歧义，先确认用户所指范围。以实际代码和记录为依据，只读讲解，业务任务沿用已有阶段、批次和授权状态。
- **联调问题、Bug 或优化。** 读取[问题排查到改动交付](references/问题排查到改动交付.md)，按当前证据及确认状态接续。先用[问题排查](../sdlc-issue-investigation/SKILL.md)查清并汇报，再用[改动方案确认](../sdlc-change-proposal/SKILL.md)提交方案。用户明确确认后，才进入分支选择和获准批次实施，按约定复测并同步受影响的文档。要求立即修复时同样检查这些前置条件。
- **新功能入场。** 默认从项目现状评估开始，在目标仓库定位相关实现或依据，提交调研草稿和理解回执。已有有效调研确认时，接到第一个仍需完成的阶段。开启入口或接收资料本身不授予编码权限。
- **回看。** “回看 R05 的状态查询契约”应查阅相应资料，回答问题并给出依据。保持正式阶段、批次和授权记录。
- **修订。** “重新讨论 R05 的返回字段”先形成差异和影响说明；经人确认后同步受影响的主记录、批次和验收条件。
- **实施。** 点名批次实施与验收时按当前实际授权判断可执行动作。联调问题、Bug 或优化的实施仍须满足对应流程的方案、分支和批次条件。若用户明确表示“B01 已通过，按计划 v2 执行 B02”，分别记录验收与新批次授权，满足 B02 开工条件后实施本批。未获授权时，提供具体待决定事项。
- **接续与落盘。** 新会话优先调用任务上下文恢复 Skill 核对任务身份、有效决定、实际状态、授权和在途事项，输出恢复理解。经人工确认接续正确后，在有效授权内恢复相应工作。正常阶段落盘按当前阶段规范执行，在需要核对版本、变更或接续状态时使用任务上下文恢复 Skill。

面向用户先给本轮实际结果，再给关键依据、阶段产物位置、需要确认的决定及下一步边界。仅为已发生的工作更新进度。
