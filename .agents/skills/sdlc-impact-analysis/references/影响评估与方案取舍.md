# 影响评估与方案取舍

围绕已确认的需求，给出每项改动的影响链、可行方案和实施顺序，让人能够决定采用哪条路径、哪些底层工作需要先处理，以及什么条件下可以继续。

## 确定分析对象

读取有效的需求与验收案例、现有实现与版本、已知约束和既定路径。对重要对象做定向只读核对，标明证据适用的代码、环境和版本。部署、数据量、外部消费者或前置批次状态无法核实时，保留条件和验证安排。仅暂停依赖这些前提的判断。

从每个关键需求逐步追踪到变更对象、读写方、消费者和受影响的用户行为，直至可以解释取舍。无需改动的部分可以引用现有能力和复用条件。没有识别到外部消费者时，记录查找范围和剩余不确定性。

每个实质性改动记录以下内容。

| 信息 | 必需内容 |
| --- | --- |
| 理由与来源 | 关联的已确认需求或案例、现状依据、变更必要性 |
| 对象与行为 | 拟新增、修改、停用、替换或复用的对象及行为 |
| 受影响方 | 调用方、共享能力、数据、配置、鉴权、运行中任务或外部依赖 |
| 兼容与顺序 | 旧行为、旧数据、新旧版本共存、必须先处理的工作 |
| 风险与验证 | 触发条件、后果、缓解、验证办法、失败处置及处理角色 |
| 状态 | 核实的事实、推断、候选建议、待验证前提及已有决定 |

## 检查数据和公共能力

**数据库与存储。** 确认变动对象及复用可能性。说明历史数据、默认值、空值、重复值和存量转换如何处理，并核对哪些进程仍可能读取或写入旧结构。列出迁移、应用发布、回填和清理的依赖顺序。分析相关锁、长事务、并发写入、中断与重复执行。没有实测时将耗时、容量和负载影响标为估计或未知。

**版本共存与恢复。** 分别检查升级前、新旧实例同时运行、升级完成和应用回退后的行为。对删除、语义变更或不可逆转换，说明备份、恢复、补偿或前向修复的前提、触发条件及待验证部分。代码回退、数据恢复和外部动作补偿分别给出结论。

**公共契约。** 定位接口、Agent 工具、共享组件、事件和消费者，核对字段含义、默认值、返回、错误、权限、异步状态、回调及兼容窗口。标明部署顺序和需要对方配合的事项。新增返回字段也可能影响严格解析的消费者；使用已有调用证据判断实际影响。

**运行行为。** 涉及 Agent 编排、模型配置、提示词、检索、文件、缓存或任务状态时，仅检查与变更相关的路径。若发生恢复、重试或取消，说明旧任务和已产生副作用如何处理。写入超时而结果未知时，先用原操作标识核查实际状态。无法查明则保留待核查状态，交给人决定处理方式。禁止重放结果未知的写操作。

## 比较实际可行的方案

在相同需求、权限和验收预期下，比较实现思路、复用点、必要改动、兼容性、主要风险、恢复限制、外部协调、验证成本和预期代价。分别标注测量结果、基于何种依据的估计和未知项。只有一条合理路径时，说明其成立条件和排除其他路径的依据。

用户已有明确路径时先核验它，存在冲突则给出证据及可选修正。优先推荐满足已确认目标且额外复杂度较低的路径。引入新服务、框架或多 Agent 时，指出哪项需求或已核实限制使其必要。

针对推荐方案，写明“哪项事实会改变推荐”。例如，采用现有存储依赖特定查询能力，可给出最小核验方法和失败后改选的方案。关键风险影响可行性时应先解决或排除对应范围；可推迟的核验必须有执行时点、证据判据和失败后处置。已有方案讨论、脚本或历史备份的存在，只能作为证据起点。

## 提交路径与决定

将候选方案、AI 推荐和人的正式采用决定分别记录。请求人确认采用路径、范围及排除项、数据库和公共接口调整、兼容取舍、前置项顺序、风险与未决条件。复用仍有效的已有决定，标明实际确认的版本与范围。若方案要求改变业务预期，先提交业务差异供人决定。

正式分析时，在任务目录写入 `03-改动与影响范围.md` 草稿，核对落盘内容并更新任务 README。优先沿用项目路径，缺省为 `docs/ai-development/<任务名称>/`。回执中提供影响最大的变更、推荐理由、必要前置项和具体待决定事项。回看已有方案只需说明对应决定、条件与出处。

方案获确认后，将采用路径、影响对象、依赖顺序、外部配合和验证限制交给功能责任划分。未满足关键条件时明确受阻范围。方案发生实质性变化时记录替代关系，只重新核对受影响的判断与验收依据。

## 底层前置工作需要单独放行

本次分析默认只读并可维护任务文档。若必须先实施底层调整或以实验核实方案，单列前置批次：给出具体目标、操作对象、环境、允许范围、依赖、验证判据、恢复限制和待决定事项。覆盖该批的人工授权和实际启动条件满足后才执行，实施与人工验收分别记录，再把结论带回方案。已有且未变化的有效决定不重复审批。方案确认和环境执行的依据分别核对，禁止因方案已保存而自动迁移、发布或继续后续批次。
