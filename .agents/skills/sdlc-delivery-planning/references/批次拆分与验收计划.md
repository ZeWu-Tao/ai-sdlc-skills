# 批次拆分与验收计划

把当前任务拆成一组能单独授权、验证和人工验收的工作。每一批都要能回答：用户或评审人能看到什么结果，通过什么实际证据作出判断，这批做到哪一步就停止。

## 选定批次边界

1. 从已确认的功能与业务案例提取可检查的交付结果，核对采用方案、功能责任、接口契约、新旧版本兼容限制和已知风险。记录使用的版本及有条件的部分。
2. 遵守契约、实现和验证活动各自的前置条件，结合业务优先级、复杂度与风险安排顺序。运行时的接口先后只约束相应调用流程。允许并行的工作在计划中标明；跨批执行仍按每批实际授权。
3. 按一个可观察的结果组织实现、相关内部逻辑和必要检查。若一项工作只能在后续尚未实现的批次中判断成败，应调整拆分、依赖顺序或经人认可的验证边界。
4. 数据变更、共享能力或验证技术假设可成为前置批次。此类批次说明产物、验证判据、影响环境和后续选择。沿用已有前置批次的实际状态，先核对未知动作；改编号时保留映射，禁止因此重放写入或重复处理已完成的操作。
5. 检查每个确认功能、接口及必要配套事项在某一批有所归属，或有明确的排除、延期、外部交付安排。单批以便于评审、调试和隔离问题为准。

例如，若本批目标为“创建草稿并可重新打开”，一批可包含创建、读取及必要的权限和存储处理。验收从创建开始，用返回的标识重新读取并比对正文及归属。若本批仅交付异步任务受理，应验证任务已登记并可查询，把最终生成的验证明确安排到另一个有条件的批次。

## 写出单批执行卡

| 项目 | 必须记录的决定 |
| --- | --- |
| 批次与目标 | 稳定编号、计划版本、预期业务结果或技术验证目标、对应需求与案例 |
| 内容和边界 | 包含和排除的功能、接口、内部处理、允许修改的对象、兼容限制、外部承担内容 |
| 依赖和时点 | 哪项契约、实现、数据、环境或外部配合在哪个活动前就绪，实际状态、依据、未满足时阻塞什么 |
| 可验证过程 | 输入和前置状态、真实处理路径、输出或可观察变化、独立核验结果的方法 |
| 交付与验收 | 产物、测试与人工检查范围、预期证据、验收判据、确认角色、失败处理 |
| 授权 | 当前批次标识、获准范围、涉及环境及带副作用的操作、实际确认依据 |

用“已约定、已交付、已核实可用、待核实”等准确状态描述依赖。业务上需要外部数据时，可以先讨论模拟条件下可独立检验的范围，记录能证明什么、不能证明什么、真实验证安排在哪一批、条件和责任人。有阻塞时先说明哪项活动受阻。只对获准且满足前置条件的部分推进，向人提出重排建议。

## 测试和人工验收

按改动选择必要检查。计划先于实施，记录以下信息：

- 哪条成功路径和哪类实际相关的异常可能使结果偏离预期。按任务选择权限、错误、结果未知、重复操作、取消、状态恢复或兼容情况。生成质量涉及不确定性时，明确样例、观察维度、判据与人工检查角色。
- 准备在哪个环境、使用什么数据、用什么触发动作验证，怎样观察输出、落库结果或业务副作用。列出自动检查、必要人工调试和相关回归，以及需保留的差异、运行记录或实际产物。
- 当测试需要真实写入、付费调用、外发或清理数据时，明确授权覆盖的环境、对象和边界。尚不具备该条件时保留验证缺口，并标明可做的独立工作。
- 模拟验证、真实链路验证、未执行、受阻和失败分别记录。只有达到事前约定的判据，才可报告相应范围验证通过；本批人工验收须依据人的实际判断。
- 执行后如需修改预期，记录原条件、变更原因、影响、人的决定及未完成义务去向。不能为消除失败记录而降低既定判据。

## 计划确认、批次授权和进入实施

计划提交时，列出整体覆盖、各批顺序、排除项、前置批次、模拟与真实验证的分工、关键判据和需要人的决定。将草稿保存在项目任务目录的 `06-开发批次计划.md`，在任务 README 中登记有效版本、当前授权和待办。执行记录由实施时填写。

| 当前决定或事实 | 下一步 |
| --- | --- |
| 计划已确认，没有指定执行批次 | 记录“计划已确认、待授权”，等待具体批次放行 |
| 某一批明确获准 | 核对该批版本、目标、允许修改对象、操作环境、真实前置条件、测试与验收安排，就绪后进入该批实施 |
| 本批实现已提交、人工待验收 | 等待人检查或按反馈修正本批 |
| 本批验收未通过 | 在原授权内修正并重新交付，涉及改范围时先提交调整 |
| 本批已通过，下一批未获准 | 更新本批验收记录，等待下一批指令 |
| 本批已通过，下一批已明确获准 | 复核下一批就绪条件和授权，才开始该批 |

同一条明确指令可以确认计划并授权首批，也可以验收本批并放行指定下一批。分别记录两个决定的对象和范围，沿用仍有效的授权。必要依赖未就绪时标明阻塞，只有获得明确的局部推进许可才执行可独立部分。初始批或被单独授权的前置批次按其实际依赖开工；后续批次核对上一批的人工验收。

拆分、合并、改名、移项、重排时，记录旧标识与新标识的关系。仅重命名且全部实际条件一致时可复用有效授权。范围、操作环境、验收预期或权责发生实质变化时，更新计划并取得针对受影响部分的确认。局部计划通过仅覆盖明确条目，未覆盖部分继续保留待确认状态。
