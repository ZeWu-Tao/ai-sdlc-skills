# 接入说明与联调验收

围绕接收方要完成的业务动作组织交接。先定位双方版本、目标环境和实际契约，再用一条完整的调用路径说明如何使用，并用约定场景验证接收方确实能够接入。

## 确定本次交付和依据

从任务记录识别接收方、本人职责、已验收功能、交付范围、排除项和验收条件。明确当前委派覆盖文档编写、实际发送、对接指导、真实联调、环境操作中的哪些动作。仅要求文档时，完成可供人审核的材料，另记联调待办。

核对接口实现和调用代码、有效设计、已确认变更、实际批次验证及目标环境。分别登记文档、契约、服务或组件版本、已部署环境和实际验证范围。没有提交号时，可使用能复查的工作区差异。缺少真实地址、版本或可用性证据时，标注待核实和提供方。

| 核对所得 | 可写入交接材料的结论 |
| --- | --- |
| 实现和有效契约一致 | 写明实际调用方式、适用版本与可用环境的证据。 |
| 变更已经确认且实现已更新 | 列出变化、适用版本、旧调用方的兼容和接入方需要调整的部分。 |
| 实现和已确认契约冲突 | 标明冲突、受影响场景及证据，提出修复或契约变更决定。禁止通过改写文档将缺陷认定为预期。 |
| 仅有设计或代码定义，缺少运行验证 | 指出已知内容、未验证条件和限制。将规划、占位和本期范围外能力单独列出。 |

## 编写接收方可使用的接口说明

沿用实际的接口形态，如 HTTP 方法与路径、工具名、公共函数、消息或事件。按业务调用顺序说明前置资源、身份与权限、每一步需要的输入、从哪里取到下一个标识、如何读取最终结果。

每个接口应说明以下内容。

- **输入与输出。** 字段位置、类型、业务含义、必填条件、缺失与空值含义、默认行为及取值限制。分页、排序、单位、时区等按适用范围填写。
- **身份与资源。** 可信身份来源、允许的操作和资源范围、拒绝条件、输出可见范围及凭据取得方式。仅使用可替换的示例值。
- **错误与重试。** 区分传输结果、业务错误和执行结果未知。给出主要错误类别、可识别值、调用方处理动作、重试前提及状态核查方式。
- **写操作。** 说明副作用、重复请求含义、操作标识、去重范围和限制。超时后结果未知时先核查原操作。无法核查或安全去重时，记录等待、停止或人工处理路径。
- **异步、流式、事件或取消。** 按需说明已受理、执行中、部分输出、最终结果的差别，以及任务标识、合法状态、断开重连、重复或乱序事件、取消后的实际效果。
- **示例与维护。** 给出典型输入、关键成功分支、代表性错误和可检查结果。标识哪些是经脱敏的真实响应（含版本与环境）、哪些是构造示例、哪些尚未运行。条件允许时附与实现一致的 OpenAPI、工具 Schema 或可运行样例，列出副作用及调用前提。

逐项核对示例与实际字段、权限和状态。例：创建端返回 `taskId`，示例还必须按实际契约说明怎样查询结果、哪些状态算完成、错误或取消后如何处理。接口若只完成受理，结论写到受理为止。标识仅为示例，实际项目沿用真实命名。

文档、附件和联调证据按接收方授权范围提供。凭据、未脱敏日志、无关用户记录等不得写入示例。单独记录材料实际发送、接收和可访问状态。

## 核对接入理解

交接时，请接收方或其 AI 以自己的话说明业务目标、适用版本、调用顺序、关键输入来源和结果传递，并推演正常场景及重要异常场景。回执应列出权限、超时重试、异步状态的处理、拟修改对象、待确认差异和测试范围。双方按职责确认影响业务或对接契约的决定。接收方的实现与环境操作按其已有授权进行。

在当前任务仅授权准备材料时，将需要转交的对象、文档位置和待确认事项列给用户。实际收到回执后，再记录理解确认。AI 回执、发送成功、无回复都不能代替相关人员的人工验收。

## 执行联调并处理问题

实际联调前核对调用方、提供方的版本、环境、授权、测试数据、就绪依赖和副作用。用真实的接入实现与提供方实现执行约定场景，记录关键请求或关联标识、响应、接收方后续处理，以及可核对的最终状态。按相关性覆盖正常、权限、异常及状态变化。模拟环节、单方自测与端到端联调分别记录。已有证据只在版本、环境和场景仍适用时复用。

| 问题 | 处理与复验 |
| --- | --- |
| 文档失实或遗漏 | 根据有效契约和实际实现更正文档，标出受影响的示例和调用方。 |
| 本方实现缺陷 | 在有效修正范围内处理，超出授权时提交影响和建议。记录修复版本并重测相关场景。 |
| 双方契约冲突或新增需求 | 列明来源、期望与实际结果、兼容影响和决定人。取得决定后同步双方约定。 |
| 环境或外部资源受阻 | 记录缺口、阻塞场景、负责人和解除条件。其余独立场景按已授权范围继续。 |
| 写请求结果未知 | 使用已有授权核查原请求或业务状态，记录实际可确认的部分。禁止重放写操作来试探结果。 |

## 确认交付结论

按目标项目的约定将接入说明保存到本次任务的对接文档，引用批次和联调证据，在任务入口登记对接文档的实际位置与最新状态。每次有效契约变化，更新版本、适用范围、理解回执和受影响场景的复验结果，并按既有授权通知有关接收方。

1. 仅交付资料时，记录文档版本、审核结果、交付对象、实际接收状态和联调待办。
2. 确认约定范围对接完成，必须具备一致的实现和契约、接收方可获取的材料、可核对的理解、必要真实场景的证据、问题处置及人的明确验收决定。
3. 局部交付、问题延期或范围调整须记录原范围、实际决定、未完成义务和负责人。上线与验收分别记录。需要外发、直接修改双方项目、调用真实业务接口或发布时，核对相应授权。
