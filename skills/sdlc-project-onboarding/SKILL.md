# 熟悉整个项目

在目标项目做一次只读走读，让用户听懂项目怎么运转，也让后续开发有一份能回到源码核对的记录。用户说「熟悉整个项目」时直接开始。用户同时举了一个想加的功能，就用它检验理解。实际开发沿用用户对那项任务的授权。

1. **从全貌找到主线。** 确认仓库根目录和当前版本。Git 项目标明分支、提交和与本次走读有关的未提交变化，其他项目注明所读快照或日期。盘点顶层目录、服务或包、入口与适用的目录规则。读取本 Skill 配套资料《项目走读与开发示范》，按指南追踪核心路径、技术用途和同类实现。先补读说不通的连接点，再判断哪些部分已经熟悉。
2. **讲给接手项目的人听。** 先用几句话说明谁用这个项目、做什么、从哪里开始用。展示带逐项目录说明的分支树，结合真实场景解释各部分怎么协作、用了什么框架、为什么这样设计。项目大时按服务或业务域分段讲清，保留整体目录索引。关键判断附仓库相对路径和符号、配置项或文档章节。
3. **用下一次开发检验理解。** 选用户举的例子，或选项目里确实存在的一类扩展。用第一人称逐步说出「我会先看哪个实现、把新内容放哪里、如何接到现有入口、最后怎样验证」。让用户能顺着文件找到每一步。关键连接还没找到时，明确哪一步待查，给出已经能确认的部分。
4. **把开发依据留在上下文里。** 在当前对话结尾留下简短的「后续开发约定」，包含适用仓库与版本、入口或参考实现、文件放置与命名、接入方式、验证入口及影响开发的未决项。写明依据属于项目明文约定、同类代码惯例还是本轮推断。后续开发先沿记录定位，再核对要改目录的当前规则和同类实现。分支、目录或接入机制变化时更新受影响的结论。

讲解架构或演示开发时，按本 Skill 配套资料《项目走读与开发示范》的「选图与核对」一节选择呈现方式并核验成品。理清跨服务调用时用时序图，对照「现在怎么运行」和「新增功能会改哪里」时按「交互路径图」一节制作可点开的路线。把图中的关键结论对应到本轮核实的项目依据，并保留带说明的目录树和后续开发约定。

默认在对话中交付。用户要求落盘或供新会话复用时，优先更新项目已有的交接或架构笔记。若还没有此类记录，按用户指定位置或目标项目实际的文档组织方式保存，并告知下次从哪里读。保留维护人已有内容，标出本次查看的版本与待核实项。只读要求下，把同一段记录交给用户复制到下次会话。正式项目规范的修订另按维护人的要求处理。
