# 现状调查与证据记录

从本次需求相关的一个真实入口追踪到可观察结果，使负责开发的人能判断参考对象是否正确、哪些能力可复用、哪些结论仍需验证。

## 定位调查对象

- 从用户指定的仓库、模块、相关资料和参考功能开始。已有任务先核对任务入口中仍有效的结论与未决问题。
- 从用户描述抽取本次需要回答的问题，列明检查范围、必要的直接依赖和排除项。项目或目标有歧义时，先在已知目录中做最小只读定位，再提交需要人选择的候选对象。
- 登记资料的实际读取情况。缺少需求文档可以直接查项目代码。链接打不开、附件缺页或资料版本未知时，记录其影响，继续完成有依据的部分。
- 将静态阅读和已有授权覆盖的核查用于现状调查。启动服务、安装依赖、运行有副作用的脚本或访问外部环境前，核对相应授权。发现业务缺陷时记录证据与影响，修复工作依据另外明确的任务范围进行。

## 追踪一条关键路径

从入口列出实际经过的校验、处理、依赖调用、持久化和结果返回。依据项目实现选择适用环节，同时指出影响该路径的重要失败分支。每个节点关联代码符号或资料章节，并说明其在路径中的作用。

判断可复用能力时，核对调用条件、输入输出、权限、适用范围和已有消费者。涉及异步任务或业务写入时，沿实际调用检查任务状态、恢复、重试、取消或重复执行的处理位置。记录能定位的逻辑和仍缺少的证据。能够解释目标路径、定位关键依据并列清缺口后即可结束深入追踪；扩大到其他业务域或全面审计前需说明必要性并核对授权。

## 给结论配证据

| 记录类型 | 需要提供的依据 | 合适的结论范围 |
| --- | --- | --- |
| 现状事实 | 仓库相对路径与符号、文档章节或配置项；注明版本、分支或工作区状态 | 该来源直接显示的定义或行为 |
| 运行结果 | 已执行的检查、环境、版本、输入、输出及证据位置 | 该版本和场景实际观察到的行为 |
| 静态推断 | 已读代码之间的关系、推断前提和验证办法 | 有待运行或其他证据验证的解释 |
| 建议与缺口 | 建议理由，或未能核实的内容、影响和补查安排 | 待人选择的方向或待核实的问题 |

例如，只看到保存函数向存储对象传入草稿状态，可以说明这条代码路径调用了草稿保存能力；要声称草稿已经持久化，需要对应环境的写入和回读证据。检索未命中时写明搜索过的范围，保留仓库外实现或其他入口的可能。代码和文档不一致时分别引用两方，说明差异影响哪些后续判断。报告中仅保留必要且适当脱敏的证据。

## 形成可审查的理解

正式调研时，依目标项目约定保存现有项目理解记录。更新当前任务入口，登记有效报告和当前状态。单纯回看既有决定时，直接返回出处和当时证据覆盖的范围。

向用户提交简要回执，说明参考对象及理由、关键路径、可复用能力、证据位置和未核实项。请用户确认调研范围、主要现状理解、可沿用的约束，以及影响后续工作的资料缺口如何处理。

只有确认依据可定位、关键结论可复核、阻塞缺口已解决或有明确处理安排时，才将对应内容标为已确认并更新入口。文件写入、静态推断和人工确认分别记录。重要事实发生变化时，修订受影响结论并保留旧决定与修订关系；未变化的有效确认继续沿用。完成后可依据已确认范围整理新的业务需求，编码和环境操作仍依对应任务授权执行。
