# 需求分析与确认

开始时读取[业务场景与理解回执](references/业务场景与理解回执.md)，按目标项目的适用约定处理当前请求。已有任务按任务 README 定位有效阶段文档和当前授权。回看请求直接给出已确认结论及出处。仅当用户要求整理、修订或正式推进时，按授权写入相应任务记录。

1. 提取需求、原型及补充说明中的目标、角色、范围、输入输出和排除项，引用当前有效的现状依据。
2. 区分明确要求、现状事实、AI 建议和假设。选择能区分两个不同业务解释的案例，描述用户操作及可观察结果。
3. 实际整理时保存 `02-业务需求理解.md` 草稿，提交回执。按人工确认的具体条目更新状态和任务 README，进入影响分析时保留未决条件。

用户需要找产品确认时，用具体场景写明待定的业务结果和希望对方确认的问题，给一段可直接复制的正文，由用户自行发送。可用时参考[对接沟通草稿](../sdlc-integration-handoff/references/对接沟通草稿.md)。
