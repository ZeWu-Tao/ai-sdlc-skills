# 任务记录与会话恢复

维护任务文档时，将已确认决定写入对应主记录，再更新任务入口。接续工作时，先还原目标、有效决定、实际执行位置及授权边界，使人能逐项检查准备恢复的动作。只读取或回看既有结论时，可以直接回答其出处和适用范围。

## 选择记录位置

按目标项目的约定定位已有任务入口。新任务需要建档时，沿用该项目同类任务的记录方式。项目尚无约定或先例时，在目标项目为这项任务建立可持续更新的入口，记下实际位置。每项决定选定一个主要记录位置，其他文件保留必要摘要和引用。先核对任务标识、目标、仓库或工作区及适用环境，避免将同名任务混在一起。

| 处理对象 | 主要记录 | 写入时机 |
| --- | --- | --- |
| 目标、阶段、当前批次、有效文档和授权摘要 | 任务入口 | 阶段变化、重要决定、交接或准备接续 |
| 项目现状、业务需求、改动影响、负责范围、接口契约 | 依次对应阶段成果 01 至 05，各自维护相应主记录 | 形成草稿、收到确认或发生实质变更 |
| 批次计划、顺序和允许范围 | 开发批次计划（成果 06） | 计划、当前授权或批次边界发生变化 |
| 实际实施、测试和人工验收 | 各批次独立的执行与验收记录，以实际批次标识区分 | 开工、实际结果变化、交付及验收 |
| 接口交接、联调和交付决定 | 对接文档（成果 07）或其关联记录 | 对接材料、真实验证、问题处置或验收变化 |

入口应指向实际形成的记录。将恢复回执放在入口相应章节或项目约定的位置。保留关键事实及其凭据所在位置，无需保存逐字聊天或创建未开展工作的空报告。

## 保存决定并核对写入

1. 用实际来源、已核实的现状和任务范围形成草稿。区分已有决定、AI 建议、推断及未决项；未确认内容清楚标为“草稿”。
2. 从用户指令或可核实的既有决定提取确认主体、对象、版本、范围和附带条件。确认、验收、下一批放行可能出现在同一条指令中，分别记录其含义。有效决定可直接引用。
3. 保存前核对目标路径和协作人员的变化。先更新主记录，再回读实际落盘内容，与人的确认核对。然后同步入口、引用及受影响的相关记录。
4. 记录实际保存的位置、重要变化、同步失败或仍未完成的部分。发现部分写入或链接失效时，在已有文档维护授权内恢复一致性。暂停依赖缺失依据的动作，继续已允许的独立核对。

## 区分版本、事实和授权

| 判断对象 | 必须能追溯的依据 |
| --- | --- |
| 文档修订及状态 | 版本、更新时间、已确认的内容范围、草稿、已被替代的决定和替代关系 |
| 事实与验证 | 对应源文件、代码或工作区状态、环境、验证方式、实际结果及限制 |
| 业务决定与人工验收 | 用户或指定人员的实际决定、指向的对象、版本、范围和仍待满足的条件 |
| 批次与操作授权 | 项目、批次、允许对象、动作、环境和限制，以及后续的恢复、暂停或撤回决定 |
| 接续理解 | 本次回执、用户对其具体内容的确认及当前仍存在的缺口 |

优先记录实际消息、评审、工单或文档定位。缺少稳定标识时，写明可核对的来源和决定摘要。禁止虚构审批号、签名、提交号或确认时间。版本更新、新草稿、AI 摘要和入口中的“已授权”字样均不能自行产生授权；局部确认必须保留边界。历史测试结果应关联其当时的交付版本。

## 处理变化和冲突

- 人最新的明确决定在其适用范围内替代旧决定。记录变更源、原结论和新内容，沿引用检查受影响的业务规则、接口、批次、验收和授权。未受影响的有效结论可继续沿用。
- 根据变化对象选择依据：业务范围和授权查人工决定，代码或运行事实查可核实的现状。发现实现偏离已确认需求时，记录差异并提出决定事项。文件最新时间、入口摘要或 AI 推测不能解决语义冲突。
- 对已确认文档提出修改时，保留原决定的有效内容和可追溯历史，并单独标识拟议修订。并行修改有重叠时保护现有工作，说明冲突所在和影响，仅暂停有争议的动作。
- 记录缺失时可按授权整理带证据和限制的重建草稿，保留未核实项。任务身份无法唯一确定时，只在已知范围定位候选并请用户选择。任务记录只保留必要信息，对密钥、密码和无关敏感数据进行排除或脱敏。

## 恢复读取顺序

1. 确认要接续的项目、任务和当前请求。核对与本轮工作有关的项目约定、资源范围及读取权限。
2. 读取实际任务入口，优先识别当前阶段、批次、暂停或撤回指令、授权依据、未完成和结果未知事项。
3. 根据入口读取拟恢复动作所需的有效阶段文档、批次计划、执行或交付记录。存在版本冲突时沿实际引用查找主要决定。
4. 按需补读直接影响本次判断的需求、契约、验收或变更证据。历史材料只在解释决定或差异时读取。
5. 核对必要的代码、工作区改动、运行环境、依赖和在途动作。资料缺失或能力受限时明确可见范围，以及受阻的判断。
6. 汇总当前能沿用的决定、与现状的差异和拟恢复的具体工作。回看请求可以至此交付。恢复实施请求按下节形成回执并等待接续确认。

## 恢复回执与执行判据

回执应让用户能回答“准备在哪个任务、哪一批、哪个环境继续做什么”。附所读文档与核对范围，标出已验收的具体版本、授权依据、排除项、暂停记录、在途或结果未知动作、关键差异、拟执行内容和需人决定的事项。

恢复实施必须同时满足以下条件。

- 人已检查并明确确认本次接续理解，修正结果已纳入任务记录。
- 原授权仍覆盖该任务、批次、资源、操作和环境；否则应有相应的新授权。改路径或换会话后核对身份和授权的实际覆盖范围，对未变化决定复用其依据。
- 最近有效的停止、暂停或撤回决定已被识别。仍有效的暂停须由人明确解除；恢复理解获确认只覆盖相应回执。用户可以在一次明确指令中同时确认接续、解除暂停并指定获准动作。
- 当前动作的必要前置条件已满足，依赖未知结果、失效证据或未决冲突的部分继续暂停。
- 主记录和入口反映此次确认、可恢复范围、未决项及证据限制。局部恢复仅限已确认且获授权的独立部分。

在等待确认期间可以做已获准的只读核对或文档整理。对已执行、在途或结果未知的写入、发送和发布，使用授权范围内的状态查询或去重证据核实。禁止通过再次执行同一写操作探测结果。分别记录取消请求、执行终止、数据恢复和业务补偿的实际效果与操作权限。

示例：任务入口写有“B02 已获准”并记录了更新的“暂停 B02，先核查请求 T4”。应报告 B02 当前暂停、T4 结果待查，给出可用的只读核查入口。即使用户确认这份摘要准确，仍要取得解除暂停的明确决定才能继续实施。

## 可复制的任务记录

下列三份模板分别用于任务入口、阶段记录和新会话理解回执。项目已有结构时复用对应字段。

### 统一任务入口

```markdown
# 任务入口

## 任务身份与当前范围
- 任务标识、目标和负责范围：
- 项目 / 仓库 / 工作区及适用环境：
- 当前阶段、当前批次和实际状态：
- 明确排除项和关键限制：

## 有效文档索引
| 记录对象 | 主要文件位置 | 有效版本 / 确认范围 | 文档状态 | 待确认修订或保留问题 |
| --- | --- | --- | --- | --- |

## 关键决定与当前授权
- 当前目标、采用路径和重要约束的摘要及主记录：
- 当前获准批次、修改对象、环境与允许操作：
- 授权的实际来源、覆盖范围和保留条件：
- 暂停、停止、撤回或恢复指令及影响：

## 实际进度与证据
- 已完成实现及其版本 / 工作区状态：
- 已验证内容、环境、范围、限制及证据位置：
- 已人工验收批次和对应版本 / 范围：
- 在途、结果未知或需要核查的动作：
- 对接、联调与上线状态，如涉及：

## 未决事项与下一步
- 问题、影响范围、处理角色及解除条件：
- 当前允许继续的工作：
- 需要人确认或重新决定的事项：
- 尚未完成的文档同步或证据核对：

## 最近恢复与变更
- 最近读取和核对的材料、实际范围：
- 恢复理解回执位置及人工确认结果：
- 拟恢复动作及适用授权：
- 重要变化、原决定与替代关系：
```

### 阶段记录与决定变更

```markdown
## 文档元信息
- 任务标识与适用阶段 / 对象：
- 文档版本、更新时间：
- 文档状态：草稿 / 已确认 / 已被替代
- 已确认内容、实际依据和覆盖范围：
- 未确认部分、假设与保留限制：
- 相关代码 / 契约 / 环境 / 证据版本，如涉及：
- 主要关联记录与任务入口：

## 重要变更
| 变更及来源 | 原结论与依据 | 新内容 / 状态 | 受影响范围 | 需要重新核对或确认的部分 | 已同步与待同步记录 |
| --- | --- | --- | --- | --- | --- |
```

### 接续理解回执

```markdown
# 恢复理解回执

- 接续任务、项目与范围：
- 实际读取的入口、有效文档和版本：
- 没有读取或仍需核对的关键资料：
- 我方当前理解的目标、业务规则、采用路径和限制：
- 当前阶段 / 批次，已完成及已验收的真实范围：
- 可继承的授权、依据、环境与操作边界：
- 暂停、撤回、在途和结果未知事项：
- 历史记录与当前现状的差异：
- 拟恢复的具体工作，以及不会纳入的范围：
- 仍需由人明确的事项：
- 人工确认结果及其实际覆盖范围：待确认 / 实际决定与依据。
- 恢复实施条件：理解确认、有效授权和对应前置条件分别满足后，才恢复相关工作。
```
