# 接入与使用

## 接入项目

1. **项目配置**。将包中 `项目配置/` 里的 `AGENTS.md` 和隐藏目录 `.rules/` 放到项目根目录。已有项目先合并自己的约定，保留已填写的目录、命令和环境信息。macOS 访达可按 `⌘⇧.` 显示隐藏目录。
2. **全局 Skills**。在 Agent 的全局 Skill 列表中查找 `sdlc-orchestrator` 和需要的阶段 Skill。如果已经可用，直接点名调用。首次接入时，使用当前 Agent 的全局 Skill 管理方式导入包中 `全局Skills/` 下各个完整的 `sdlc-*` 目录，保留各自的 `references/` 与 `agents/`。
3. **填写项目规范**。由维护人补充项目根目录的 [AGENTS.md](../AGENTS.md)。团队共用的协作要求见[协同开发通则](协同开发通则.md)。全局 Skill 按名称引用，任务产物保存在实际项目中。

## 在 Codex 中调用

在 Codex 中打开目标项目。桌面端在聊天输入框输入 `/`，按名称搜索并选中 Skill，再在同一条消息中附上要求和资料。CLI 可用 `/skills` 选择，也可以在提示中直接写 `$sdlc-orchestrator` 或具体阶段名。不确定阶段时，先选 `$sdlc-orchestrator`（研发流程编排）。[桌面端斜杠菜单](https://learn.chatgpt.com/docs/app/slash-commands) · [项目级 Skills](https://learn.chatgpt.com/docs/build-skills)

| 这次要做什么 | 可以这样说 |
| --- | --- |
| 启动新需求 | `$sdlc-orchestrator` 需求和原型已附上。先参考已有教案助手，查清课程草稿能复用哪些能力，给出代码位置和待确认问题。 |
| 听现有功能的实现讲解 | `$sdlc-orchestrator` 我刚接手课程草稿。讲讲从点生成到页面拿到草稿的过程，先讲主线，有多处同名功能时先问我。也可直接用 `$sdlc-project-explainer`。 |
| 处理联调问题、Bug 或优化 | `$sdlc-orchestrator` 课程草稿联调时保存成功，但刷新后页面显示为空，相关请求已附上。先查原因和影响，再给我改动方案，等我确认后走分支选择和实施。 |
| 回看某阶段 | `$sdlc-interface-design` 回看课程草稿任务已确认的状态查询接口，说明字段含义和出处。只读回看，沿用当前进度与授权。 |
| 实施已定批次 | `$sdlc-batch-execution` 按课程草稿计划 v2 执行 B01，仅在本地实现创建和查询。按执行卡验证后提交证据，由我验收。 |
| 换会话接续 | `$sdlc-context-recovery` 接续 `docs/ai-development/课程草稿/README.md`。先给出目标、当前批次、已有授权和未决问题，等我核对后恢复实施。 |

上例中的 README 属于一次具体任务，记录阶段、进度和授权。该任务确认的接口写入同目录的 `05-接口设计.md`。项目已有任务文档约定时沿用原位置。

## 从旧版本升级

- **从 v1.7 升级到 v1.8**。更新全局的 `sdlc-orchestrator`，并导入完整的 `sdlc-project-explainer` 目录。已有项目可合并本页的讲解示例和升级说明。
- **从 v1.6 或 v1.6.1 升级到 v1.7**。更新全局的 `sdlc-orchestrator`，导入或更新 `sdlc-issue-investigation` 和 `sdlc-change-proposal` 两个完整目录。项目配置合并本包的 `AGENTS.md` 与 `.rules/` 更新，保留项目自己的约定。这三个新版 Skill 一起用于从排查到改动交付。
- **从 v1.5 升级**。合并 `AGENTS.md` 中的分支选择入口和 `.rules/` 下的更新。新增功能或修复 Bug 前先按[开发前分支选择](开发前分支选择.md)让用户通过弹窗选定分支。
- **从 v1.4 或 v1.4.1 升级**。把原 `rules/协同开发通则.md` 和 `rules/接入与使用.md` 合并到 `.rules/`，同步项目根入口的两个引用。将研发流程入口写为 `$sdlc-orchestrator`。如果项目与全局都装有同名 Skill，先比较自定义内容，再按团队计划归并安装。
- **从更早版本升级**。项目专属约定并入根 `AGENTS.md`，共用约定并入 `.rules/`，各阶段自定义细则并入相应全局 Skill 的 `references/`。既有任务记录继续按其原路径接续。

升级后，可让入口回看任务中一项已确认的决定，核对它选用的 Skill、实际读取的任务材料和回答依据。
